# 插件关系图 · 窄窗三套（mono 皮）

上一份 `demo/plugin-relations/` 里你选了 **02 迷你图**（大屏）。这一份只回答一件事：
**窗口窄下来，那张图怎么办。**

## 怎么看

双击 `/opt/NousDesk/demo/plugin-relations-narrow/preview.html`（单文件、字体与真数据内嵌、无端口）。

右下角三组开关：

- **窗口宽**：`1200 / 1024 / 980 / 900 / 880 / 760` —— 这是**页面自己的宽度**（不是浏览器窗口），
  骨架按 `settings.rs` 的真值摆：导航 170、列表 268（≥1000 时 292）、内容内边距 22、详情左内边距 34、
  **视口 < 900 转单栏**（详情独占，顶部「← 插件」）。上排那行小字实时报「详情内宽多少」。
- **窄窗方案**：`M1 缩列 / M2 竖排 / M3 横滑`。**只影响挤的两档**（900–999 和 <900）；≥1000 一律是你已挑的 02 原图，好让你对照「大屏不变、小屏才换」。
- **引擎**：`有 graph / 老引擎` —— 看降级（整块不出、只留一句话）。

## 先说一个测量结果

`980` 是**最挤的一档**，不是「小屏」一档：

- 980：两栏还在（列表 268），详情内宽只有 **≈445–496px**；02 的图要 448px（132+168+132+两个 8px 缝），
  刚好卡住 —— 长名字 `AboutME_ModuleRelationshipNetwork` 一压就省略号。
- 880/760：反而**转成单栏**（`< 900`），详情独占 680 / 560px，02 的图完整放得下，比 980 好过。

所以「小屏换做法」真正要救的是 900–999 这条缝；<900 那档要不要跟着换，是第二件事。

## 三套

- **M1 缩列** —— 还是同一张图：两侧列 90px、每侧最多 4 个（多的 `+N`）、hub 148px，中间照旧连线。
  「图还是图」，用户不用学第二种看法；长名字被省略号切。
- **M2 竖排** —— 窄窗放弃左右并置，改 `依赖 ↓ 本模块 ↑ 被依赖` 三段上下排，胶囊横着流，
  方向靠箭头 + 一条细线。没有连线、不吃宽度，400px 也放得下，长名字整行显示；
  代价是「枢纽感」退回成清单。
- **M3 横滑** —— 图一个像素不缩（最小 480px），放不下就让这块容器横向滑动，名字永远完整。
  同一张图两种屏一个长相；代价是要用户发现「这里能滑」，右半边容易被当成不存在，
  而且横向手势会和设置页的竖向滚动打架。

## 我的看法

**M1 用于 900–999，<900 保持 02 原图**：因为 980 只是差 4px，缩一下就好；而单栏那档
（880/760）宽度比 980 还富裕，把图换成清单是白丢信息。也就是「只有挤的那一条缝降档」。
如果嫌维护两套麻烦，就 **M1 通吃**（<900 也用 132px 大列，代码同一条路）。
