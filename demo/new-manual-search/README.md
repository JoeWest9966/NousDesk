# New Manual · 模型搜索（4 套）

`index.html` 直接双击打开（纯静态，没有依赖、没有 fetch）。

## 这一版在定什么

模型弹层现在没有搜索框 —— 242 个模型、`volc-ark` 一家就 240 个，找 `flash` 要滚五十多屏。
**加搜索框这件事没有第二种选择**，要选的是：输进去之后，**不匹配的那些怎么办**。

四个方案都是「输入了 `flash`」的同一时刻，弹层真尺寸 600 宽、真字号，直接对比。
00 是现状，用来当尺子。

| # | 方案 | 一句话 |
| --- | --- | --- |
| 00 | 现状 | 没有搜索框。往下滚，五十屏 |
| 01 | 匹配 / 压暗 | 位置全不动，不匹配的压到 32%。参考页的做法 |
| 02 | 过滤 / 只剩匹配 | 242 行变 4 行，一屏看完，不用滚 |
| 03 | 供应商折叠 | 有匹配的留着，没匹配的压成一行 24px 组头 |
| 04 | 塌成一列结果 | 搜索时三列塌成一列，一行一个完整答案（命令面板那一路） |

## 每个方案的代价（都写在页面上）

- **01**：空间不跳，但滚动量一点没少 —— 压暗只是让匹配「可辨认」，没让它们「可到达」
- **02**：最短路径，但**列表会跳**（第 12 行的东西突然变第 1 行），浏览型问题（哪家有什么）一问就看不见了
- **03**：还能知道「东西在哪家」，但一个搜索框配了一套手风琴 —— 组头、计数、展开箭头全是噪音
- **04**：一行一个完整答案，但**换了个模式**：思考档列没了，三列这个形状本身是盘面的语法

## 建议（写在页面底部）

**01 + 一条「跳到第一条匹配」**：默认保持原位只压暗，搜索框右边显示 `4 匹配`，点它把列表滚过去。
两边都要到 —— 既不跳位置，也不用手滚。

`/v1/models` 的真实模型名（242 条里取 20 条展示），供应商 `Qoder / volc-ark / workbuddy`、
思考档 `off…high`、配色 `#07c160` + 黑白灰，全部照「默认」皮。
