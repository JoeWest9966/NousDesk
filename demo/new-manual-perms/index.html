Permissions 卡 —— 一个开关，六种画法

这张卡现在写着 — / soon，是盘面上最后一处假东西。先把话说清楚： 引擎里没有 permission 这个概念（/v1/permissions 是 404，server.js 里 grep permission 零处）， 唯一存在的语义是 readOnly —— server.js:3245 那句 modelTools: body.readOnly ? { remove: WRITE_TOOLS } : null。 只读 = 不给会写的工具，别的都一样（读文件、查目录、回答问题全都在）。 所以这张卡真能表达的只有一件事：这次会话能不能动东西。 下面六套都是在回答同一个问题 —— 一个二值开关，塞进一张 230×96 的卡，怎么塞才不像设置页。

先排除两条路

不做弹层。另外三张卡都是「点开一列东西挑一个」，因为选项多。这里只有两个选项， 弹层的开合成本比选择本身还高 （而且弹层里只有一个开关，看着像 bug）。

不做成设置项。这张卡在盘面上，跟 Model / Context / Extensions 并排。 别人都是「一句话说清现在是什么」，它不能变成「一个需要操作才知道状态」的控件。

02

照 Model 卡的写法：值 + 一句解释

跟另外三张卡同一个语法：小标题、大字、下面一行灰字说清「现在这意味着什么」。 可写 → 「能改文件、能跑命令」，只读 → 「只能读，不能改」。区别在右下角那个词： 别处是 change ›（要挑），这里是 切换 ›（只有一个来回）。 整卡可点，不用瞄准一个小控件。这是我觉得最像这块盘面的一套。
