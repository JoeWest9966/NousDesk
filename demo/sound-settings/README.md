## 这一版在定什么

不是"加不加声音"，是**这十几个开关怎么摆**，以及**提示音什么性格**。
两个轴各三选一，页面顶部能切。

### 版面

| # | 方案 | 一句话 | 代价 |
| --- | --- | --- | --- |
| 01 | 一页到底 | 不分块，靠留白 + 1px 发丝线切段，开关一列对齐 | 再多两行就找不到边界，"提醒/手感"只能靠位置记 |
| 02 | 两组分块 | 两个浅底卡片 = 两件事：你不在时叫你 / 你在时回你 | 多一层底色，比一排发丝线重 |
| 03 | 两组分列 | 两栏并排一屏塞完，不用滚 | 每栏只剩三百来像素，说明被压到三行；窄窗要叠回去，两套布局都得维护 |

**建议 02**：这一页的条目会一直加（将来还有"轮到你拍板"、别的会话的事件），
"提醒"和"手感"是两种东西这件事必须写进版式，不能靠用户记位置。
03 省下的滚动量不值得多养一套布局。

### 音色（先用浏览器合成听方向）

| # | 音型 | 用在 |
| --- | --- | --- |
| A | 一音（1046 Hz，90 ms） | 完成 |
| A′ | 一音降（698 → 466 Hz） | 失败 |
| B | 二音上行（659 → 988 Hz） | 完成 |
| B′ | 二音下行（659 → 440 Hz） | 失败 |
| C | 木质（523 + 二次泛音） | 完成 |
| C′ | 木质下行（415 → 311 Hz） | 失败 |

**建议 B**：一耳朵就分得清"成了"还是"砸了"，不用记哪个音更高。
A 信息量太少（完成和失败听起来是同一件事），C 好听但"像乐器"这件事在提示音上会分心。

## 页面里那些不是开关的东西

写死成规则，不给开关 —— 少一个设置项就是赚：

- 窗口在前台、且正看着这条会话 → 不响
- 60 秒内多次完成只响一次，合并成「3 个会话有新内容」
- 音量跟系统走，页面上不另设滑杆（demo 顶部那个滑杆只为试听舒服）

## 故意做成灰的那一行

「轮到你拍板」是 `disabled` 的：引擎现在没有"工具等你批准 / 问题等你回答"这个信号。
摆一个能点的开关 = 用户点一次被晃一次（`crates/nousdesk/src/settings.rs` 开头那条规矩）。
要做这行，先去 `qrd3wh` 那边把信号要到。

## 这份 demo 里不许当真的

- 三个音色是 **WebAudio 现场合成**的，只用来听方向、音高关系。最终是随包两个 `.oga`
  （提醒 / 失败）走 `pw-play` → `paplay` → `aplay` 探测，音色还会再调一次。
- 左栏会话、图标条、设置页左侧 tab 都是背景板，用来说明"设置占右栏整页"。
- 中文字体走系统 CJK（Noto Sans CJK）；内嵌的只有 Inter 和 JetBrainsMono 的拉丁子集。

## 还没定

1. 提醒音要不要跟系统音效主题走（`libcanberra`）—— 建议不要，用户换主题我们的声音就变了。
2. 合并窗口那 60 秒，是"一个后台心跳周期"还是"取整到分钟"，得等后台心跳那条先落地。
3. 手感三个的默认值（发送开 / 停止关 / 失败关）是照"少响"推的。
