# 重命名会话 · 四套

打开 `index.html` 挑一套。

## 为什么现在点「重命名」没反应

`app.rs:4044` 那条注释说「`wire.md` 里没有改名端点」，菜单据此弹「重命名端点还没接」。
**端点是有的**，实测：

```
POST /v1/sessions/1557/rename {"name":"  改过的名字  "}
→ {"id":1557,"name":"改过的名字"}      # 引擎自己 trim 了
POST /v1/sessions/1557/rename {"name":"   "}
→ {"error":"name 是空的"}              # 400
```

所以这一轮不是「做个新功能」，是**把三条断掉的线接上**：`wire.md` 没记 → `client.rs`
没有 `rename()` → 菜单只能弹提示。（前两条已经补完了，剩下界面这一条。）

## 四套

| # | 做法 | 一句话 |
| --- | --- | --- |
| 00 | 现状 | 对照用：菜单项 + 那句「端点还没接」 |

## 我倾向 B

**骨架照微信**这条规矩直接指向它 —— 微信桌面版右键「编辑会话名」就是一个居中对话框。
而且它不用跟「点行 = 打开会话」抢命中区（A 的代价），也不用算位置和翻向（C 的代价）。

A 更 Tesla（少即是多），但输入框只有 200 来像素，`（测试垃圾 #514，可删）` 这种名字
根本看不全 —— 改名的时候看不全名字，等于没起到作用。

C 是两者之间的折中，但它引入的「第四种浮层」要单独维护一套定位。
现在项目里已经有：右键菜单、盘面弹层、抽屉、notice —— 再多一种，账不划算。

**如果你选 A**，我会把输入框做成「点进去整行剩 3 个字符也照样滚」的样子；
**选 C** 也可以，但我会先问清楚靠近窗口边界的翻向要不要做。
