# 技能 · 02（左树 + 右列表）加搜索框 · 7 种放法

分支 `design/skill-cat-demo`。双击 `index.html`，纯静态。

## 前提（决定了所有方案长什么样）

技能名全是英文（`incident-postmortem`），描述是中文（「事故复盘：时间线、根因、修复…」）。
**人记得住「复盘」，记不住英文名。** 所以搜索必须搜**名字 + 描述 + 类别名**，只搜名字等于没搜。
demo 里每套都填了 `复盘`，方便横向比。

## 七种放法

| # | 搜索框在哪 | 搜索时树怎么办 | 搜索范围 |
| --- | --- | --- | --- |
| 01 | 通栏（树和列表上方） | 不动，计数还是全量 | 当前选中的类 |
| 02 | 通栏 | **淡出、不可点，右边变成全盘命中** | 全部 |
| 03 | 左栏顶部 | 树变成"筛类别"，右边永远是该类全部 | 只筛类别名 |
| 04 | 右栏顶部 | 完全不受影响 | 当前选中的类 |
| 05 | 通栏 | 树不动，**计数换成命中数**，没命中的类灰掉 | 全部 ∩ 类 |
| 06 | 通栏 | 淡出，右边**按类别分段**显示命中 | 全部 |
| 07 | 通栏 | 完全不动 | 全部，但**不过滤只高亮** |

## 倾向 02

把「树」和「搜索」当两种互斥状态：不搜时树管事儿，一打字树让开。不用解释"现在是在全盘搜还是在类里搜"。

- 01 / 04 的坑：搜不到东西，其实是被类别框住了，用户会以为技能丢了
- 05 的坑：树上的数字既可能是总数也可能是命中数，靠颜色区分太虚
- 06 的坑：1 条命中时段头比内容还长
- 03 是给将来准备的（类别现在只有 6 个，筛类别比不筛还慢）
- **07 是唯一一个不动列表的**，技能少时手感最好；但技能到十几条就不成立了

## 落地要点

- 树从 `categories`（含空类）+ 技能自带 `category` 现算，别写死
- 子类只在父类下缩进出现（`工程 ▾ 事故`），默认折叠也行 —— 现在只有 1 条属于子类
- 左栏宽度 172、面板 620，和目录弹层同一档；技能弹层现在是 460，要跳档
