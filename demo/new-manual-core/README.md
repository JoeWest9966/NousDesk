# New Manual · 中央（hub）4 方案 × 6 状态

第一批改动里**只有外观部分**：中央那颗 `Create` + 落子之后的三件事
（禁用态 / 提交态 / 结果行）。四套方案的差别只在「中央放多少东西」。

```bash
xdg-open /opt/NousDesk/demo/new-manual-core/index.html
```

顶部 `01`–`04` 切方案（键盘 `1`…`4`），第二行切**状态**（键盘 `q w e r t y`）。
四张参数卡和虚线是固定背景，只为让人看清中央改动后和「轨道」的关系。

## 四套一句话

| # | 名字 | 这套想干什么 | 主要代价 |
|---|------|--------------|----------|
| 01 | 收拢 | 中央只留一个动作，名字 / 机器 / 目录留在底部薄栏；只把状态行补全（`ready · 本机 · …/map`） | 中央仍然空 —— 但空是这套的本意 |
| 02 | 落子面板 | 照参考页：中央直接一竖排 —— 标题、名字、机器、目录、Create、结果，dock 删掉 | 圆没了，轨道的气质弱一截；两块并排的 chip 在 320 宽里很挤 |
| 03 | 骑边 | 圆不动，机器 / 目录两枚 chip 骑在圆的下缘；名字留在更窄的 dock | 中央附近堆了三块，虚线穿过去有点乱 |
| 04 | 大圆 | 圆放大到 240，**名字输入进圆里**，机器 / 目录挂在圆外下缘，dock 删掉 | 圆里点击区变窄，长名字会被截 |

## 六个状态（每套都一样）

| 状态 | 圆 / Create | 状态行（01/02 带机器+目录，03/04 只写状态） |
|------|-------------|------------------------------------------|
| 未选模型 | 变灰、`cursor:not-allowed`、不浮动 | `no model · 先挑一个` |
| 就绪 | 白底，可点 | `ready · 本机 · …/new1/map` |
| 创建中 | `Creating…`，压到 72% 不透明，防连点 | `creating…` |
| 成功 | 白底恢复 | 绿：`✓ chat 812 created · thinking medium · skills 3 · prompt smart-ass · 本机 · …/map` |
| 部分跳过 | 白底恢复 | 黄：`创建了，但这些没装，已跳过 —— 技能：code-review、weekly-report` |
| 失败 | 白底恢复 | 红：`创建失败：会话 699 已经在活库里 —— 不用捞` |

## 我的取舍（供反驳）

- **推荐 04 大圆**：只有它同时做到「中央不空」和「轨道还在」。名字是唯一有必填感的字段，
  放进圆里最顺；机器 / 目录是附加信息，挂在圆外下缘正好。
- **02 最像参考页**，但它是「表单」，一站上去轨道就变成了背景装饰。想要「和引擎页一模一样」才选它。
- **01 最省**：改动只是状态行多带两段。如果中央空着你不介意，01 就够了。
- **03 不推荐**：chip 骑边好看，但和底下的 dock 功能重复（名字在 dock、机器目录在圆上），
  用户会犹豫「改机器点上面还是下面」。

## 落地映射

| 方案 | Rust 侧改法 |
|------|-------------|
| 01 | `board_core` 的 status 文案改 `hub_sub`；`board_dock` 不动 |
| 02 | `board_core` 换成竖排容器（`art::core_center` 改成一个盒子），`board_dock` 删掉 |
| 03 | `board_core` 里加两枚 chip（位置 `core_center + r`），`board_dock` 只留输入框 |
| 04 | `art::core_r` 放大到 240 级，`board_core` 里放 `Textarea`（圆内），chip 挂在圆下缘 |

六态在任何一套里都是同一套判定：`picked` 为空 → 禁用；`creating` → 提交态；
`flash` 有内容 → 结果行，颜色按「成功 / 跳过 / 失败」分。

数据全是假的，只为看形态。
