## 这一版在定什么

两件事，第一件是结构、第二件是这套页面的形态：

1. **关于页顶部加二级菜单**：`概览 | 插件 11`。概览 = 现在那五项键值 + 运行时/服务；
   **插件单独一页**，不再挤在概览下面。
2. **插件行要有细节**：中文名 · 英文名 · 版本 · 状态 · 类型 · 层 · 必需 · 来源 crate · 端点数，
   点开看**端点清单**和**停用原因**。

数据不是编的：faux 引擎 2026-11-19 的 `GET /v1/capabilities` 原样响应（11 个模块，
7 启用 / 4 未启用，34 条端点），类型 / 层 / 必需 / 来源来自内核 `docs/plugins.md` 的表。

### 三套插件页

| # | 方案 | 一句话 | 代价 |
| --- | --- | --- | --- |
| 01 | 列表 + 详情 | 左 268px 扫名字和状态，右侧一整页放版本/类型/层/端点清单/停用原因 | 多一栏；窄窗（<1000）放不下两栏，要退化成「点开详情占满 + 返回列表」 |
| 02 | 单列折叠 | 一个插件一行，点开就地展开详情和端点清单，不用第二栏 | 同时开三条就滚得长；端点数要扫折叠头，比对表慢 |
| 03 | 对照表 | 插件 / 版本 / 状态 / 端点四列对齐，点行展开说明和端点 | 表格感最重；窄窗要砍列（先砍端点），砍完两套布局都要维护 |

**建议 01**：插件只会越来越多（ext 运行时解冻后还会插回来），详情里的字段也会继续加；
一份「列表扫读 + 详情不挤」的结构比反复往一行里塞列省事。窄窗退化规则只有一条：
右栏宽度 < 420 时列表收起，详情顶部出「← 插件」返回，和现在设置页「返回聊天」同一套动作。

### 每行显示什么（三种方案共用）

| 字段 | 来源 | 现在能拿到吗 |
| --- | --- | --- |
| 中文名（会话 / 文档 / 技能…） | 桌面端一张 `Feature` 标签表 | ✅ 本地加 |
| 英文名（`sessions`…） | `capabilities.modules[].name` | ✅ |
| 版本 | 目标：每模块版本；现在只有 `server.version`（0.1.3，全模块一样） | ⚠ 协议没有 per-module 版本 |
| 合同 | `capabilities.contract` | ✅ |
| 状态（启用 / 未落地 / 已冻结） | `enabled` + `reason.code` | ✅ |
| 停用原因原话 | `reason.message` | ✅ |
| 端点数 + 端点清单 | `endpoints` | ✅ |
| 类型（编译期 / 声明式 / 运行时外挂） | `docs/plugins.md` 形态列 | ❌ 无端点 |
| 层（kernel / platform / app） | `docs/plugins.md` layer 列 | ❌ 无端点 |
| 必需（是 / 否） | `docs/plugins.md` 必需列 | ❌ 无端点 |
| 来源 crate | `docs/plugins.md` crate 列 | ❌ 无端点 |
| 说明 | `docs/plugins.md` 备注列 | ❌ 无端点 |
| 客户端是否登记 | `crates/nousdesk/src/capability.rs` 的 `Feature` | ✅ 本地 |

**落地顺序**：先给内核 `capabilities.modules` 加 4 个可选字段 —— `version` / `kind` / `layer` /
`required`（再加 `crate`、`description`）—— 由 `meta.rs` 的 `MANIFEST` 从 `docs/plugins.md`
生成；桌面端只负责画，字段缺失时降级（版本 = `server.version`，类型/层显示 `—`）。
**不要**在桌面端另抄一份 `docs/plugins.md` 的表当第二真相（`AGENTS.md` 的协议规矩不允许）。

## 关于页顶部菜单（固定设计，不随方案变）

```
关于                                      [概览 | 插件 11]
─────────────────────────────────────────────────────────
```

- 分段控件（segmented）而不是下划线 tab：和设置页左栏的「连接/主题/声音/关于」区分开，
  一眼能看出这是关于页内部的第二层。
- `插件 11` 带总数；选中态数字用 accent 色。
- 默认打开「概览」（跟现在一样：进来先对版本），插件是主动点开的第二页。
- 概览页保留现在五项键值，另加运行时（provider / 服务）—— 现在这些散在「≡ 更多」菜单里。

## 这份 demo 里不许当真的

- 三个方案的搜索框是真的能过滤（JS），但 11 个插件还用不上搜索；真实现建议
  **先不做**，等模块数 > 20 再加。demo 留着是为了看"放了搜索会不会挤"。
- 方案 02 默认展开第一条、方案 01/03 的选中/展开是 demo 交互；GPUI 里要真挂点击。
- `version 0.1.3` 是 `server.version` 的占位；`device` / `selection` 在 `docs/plugins.md`
  里没有独立行（它们是 server 的功能面），demo 的说明文字已注明。
- 客户端版本 `v0.9.7`、node `j1900`、地址 `http://192.168.1.7:4789` 是照线上填的样本值。

## 还没定

1. 中文标签表落 `capability.rs`（`Feature::label()`）还是 `settings.rs` 局部表 —— 建议前者。
2. 「插件」页要不要按「启用 / 未启用」分组。现在列表按 capabilities 原顺序（启用在前、
   冻结的 ext 在未启用第一个）；分组更像清单，但多两条分隔。
3. 端点清单要不要做「复制路径」—— 关于页是排查页，复制一条 `/v1/...` 去 curl 很实用；
   建议做，但那是下一层交互，不在这次版面里。
