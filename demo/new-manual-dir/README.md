# New Manual · 工作目录导航（4 套）

`index.html` 直接双击打开（纯静态，无依赖）。

## 先说 bug

目录弹层**点进去什么都没有** —— 我们从来没给 `/v1/fs/dirs` 带过 `?path=`，所以它永远返回 map 根那一层。
接口其实什么都有：

```
GET /v1/fs/dirs                        → {"path":"", "dirs":[{map 根}]}           ← 我们只吃了这一条
GET /v1/fs/dirs?path=/opt/…/map        → {"path":"…", "parent":"/opt/…/new1", "dirs":[23 条]}
GET /v1/fs/dirs?q=map                  → 按名字找
```

`:path=` 和 `:q=` 都是现成的。**所以四套方案的第一步都一样：把 `parent` 和子目录列表接上**，
那不是设计题，是接口没吃完。

## 四套在争什么

争的是**「输入框」和「面包屑」是两行还是一行** —— 它俩说的是同一句话（你在哪、怎么回去），
分成两个控件就是说了两遍；合成一个就得把「可编辑」这件事藏起来。

| # | 方案 | 一句话 |
| --- | --- | --- |
| 00 | 现在 | 一行 `..` + 一行当前目录，点进去不会变 |
| 01 | 两行：输入框 + 面包屑 | 上面打字回车跳，下面点段回去。两条路都通 |
| 02 | 一行：面包屑即输入框 | 点某段回去，点末尾变可打字。省一行 |
| 03 | 一行 + 折叠中段 | 同 02，但深路径折成 `/opt/…/new1/map`，点 `…` 展开 |
| 04 | 输入框 = 搜索框 | 打一段名字，引擎按名字找（`?q=`），点一次就到 |

## 每套的代价（页面上都写了）

- **01**：两条路都通，但两行都在说「你在哪」，460 宽的弹层里两行 ≈ 70px，正好一个子目录的价
- **02**：省一行，但**可编辑藏起来了** —— 用户得先知道「点末尾能打字」，否则永远不去点
- **03**：永远单行不截断，但 `…` 展开又是「藏起来的东西」，而且折叠规则得定
- **04**：深目录最省事，但**输入框同一时刻既是路径又是关键词**，用户得猜自己在打什么；
  模糊到什么程度由内核决定，我们控制不了

## 判断（页面底部）

**选 03**。它和 02 只差折叠一条规则，但那条规则让弹层在格子边缘也不难看；
01 的两行我嫌贵（用一个子目录的高度买了一句重复的话）。

**04 先不做** —— `?q=` 能用，但「路径框还是搜索框」的歧义没解决之前，它只会让人不确定自己打的字会被怎么解释。
等真有人抱怨「深目录点太多次」再说。

## 数据来源

`/v1/fs/dirs?path=/opt/Nous/content/new1/map` 的真实返回（map 下有 23 个子目录，页面展示前 10 个）。
弹层宽 460（Wide 档 foot 弹层的实际宽度），配色 = 「默认」皮。
