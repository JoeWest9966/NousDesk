# 扩展 · 左树 + 右列表 + 搜索 · 5 套

分支 `design/ext-demo`。双击 `index.html`。

## 「05 为啥不行」——其实行

我上一版给的两条理由，一条真一条偷懒：

1. **真的**：`内置 / 变体 / 已归档` 不是分类，它们是**状态**。一棵「按 `category` 长出来」的
   树放不下它们 —— 5 条里有 3 条在树上没位置。
2. **不成立**：「4 条配 172 宽的树太空」—— 技能那边也是 5 条配 8 个节点的树，用户点头了。
   空不空是习惯，不是对错。

⇒ 05 能做，只要树里补一组**状态**，跟分类分开。

## 五套

| # | 树的摆法 | 搜索框 | 说明 |
| --- | --- | --- | --- |
| 01 | 分类在上 · 状态在下（一条分隔线） | 通栏，树让位 | 跟技能一致，但一棵树长两种东西 |
| **02** | **状态在上 · 分类在下（推荐）** | 通栏，树让位 | 打开面板多半是为「有个坏的 / 想关一条」，状态该先露面 |
| 03 | 树只留状态，类别当行尾标签 | 通栏 | 树最短；但「看看所有跟记忆有关的」做不到了 |
| 04 | 02 的树 | **左栏顶部**（筛分组名） | 搜扩展名要去左边框，放错地方 |
| 05 | 同 02 | **通栏 + 树让位（展示搜索态）** | 跟技能弹层一个语法，零新代价 |

## 倾向 02 + 05 的搜索行为

左树 = 状态在上、分类在下（一条线切开），顶上通栏搜索框，一打字树就让位。
跟技能弹层只差「树里多一组状态」，其余全一样。
