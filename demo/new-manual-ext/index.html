我选 03 + 卡片的第 4 种（圆点）。理由：
· 弹层按状态分组，不按类别 —— 扩展这件事的真实结构是「哪些能用、哪些不能动、哪些坏了」， 不是「工具 / 观察 / 记忆」。技能那边按类别是因为技能是「挑能力」，扩展这边是「看状态」。
· 卡片用圆点：5 个点一眼看出坏了一条，数字 4/5 顺带也在。而 4 装上 · 3 核心 要读两个字才明白。

先说一件查出来的事，它改变了这套东西的重心：
写接口全都有（install / uninstall / reload / archive …）， 但 nous skills prompts 是 核心扩展 —— 引擎启动路径上硬编码 import 的，uninstall 直接返回 403 「删了下次就起不来」。加上内置的 coding-tools、加载失败的变体、归档的 demo， 这一屏上真正能拨的开关只有 123 一个。
所以这个面板的重心不是「选择器」，是「我这儿都装了什么、哪些不能动、有没有坏」。 分组（03）比分组按类别更对，就是因为这个。

还有三件要定的事：
1. 能勾的只有一个，还画勾选框吗？我倾向照画 —— 画面上「为什么这三个点不动」比「一个都不画」 更能说明架构。但核心那三条要用锁的样子，不能跟「用户只是没勾」长得一样。
2. drift: true 报不报？仓库分支没跟踪信息，pullError 一直挂着。 我倾向不报在卡上（跟这次会话无关），只在弹层底部放一行灰字。
3. 归档的要不要露？demo 是三个月前的测试扩展，露出来只会让人问「这是啥」。 我倾向默认折叠，点「已归档 1」才展开。
