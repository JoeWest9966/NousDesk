# 扩展段的三个工具放哪儿（demo）

**打开**：`preview.html`（单文件，字体与数据内嵌，双击就开，不用起服务）。

## 为什么做这个

用户反馈：「点 `扩展` 冒出来的三个选项，正好盖住 `技能` `提示词` 两个按钮。」

实测（0.9.27，Xvfb 1400 / 1200 / 1000 / 900 / 760 五档截图对比）**没有重叠**：

- 宽窗：`重载 / 垃圾站 / 类别` 在**列表头**，x ≥ 411；树列到 308 就结束，中间一条 1px 分栏线；
- 窄窗：它们在列表的**第二行**（`+ 新建` 那一行右边），段 pill 在第一行。

但**感觉得到**是对的：列表头在 y=56、树里的段 pill 在 y=92，只差 36px，又夹着一条分栏线，
两个层级的东西落在同一条视觉带上，扫一眼就像「一排按钮被顶掉了」。这份 demo 解决的是这个。

## 四套摆法

| # | 摆法 | 一句话 |
|---|---|---|
| 01 | 现状（基线） | 工具留在列表头，紧挨段名 —— 对照用，问题见卡片里的三条。 |
| 02 | 只留 `↻` | 删掉重复的 `垃圾站`（树里已有一行）和可有可无的 `类别`（树本身就是类别），列表头只剩 `↻` + `+ 新建`。 |
| 03 | 收进 `⋯` | 列表头 = 段名 + `⋯` + `+ 新建`，三个工具进浮层菜单；以后加工具不涨宽度。 |
| 04 | 次级工具行 | 列表头只留段名 + `+ 新建`；三个工具降到搜索框下一行 11px 小字（`↻ 重载 · 垃圾站 0 · 类别词表`）。 |

## 倾向

**02 打底**（先删后加：一处一个入口），若嫌 `↻` 认不出再加 **04** 那行小字 —— 两套能拼，
互不排斥。03 最保守（改动最小、列表头最干净），代价是 `重载` 从一下变两下，而它恰恰是
「刚改完文件想立刻看结果」的动作。

## 没做的摆法

- **工具挪进树**（跟类别并列）：违反 2026-11-23 那条判据 —— 树里只放类别，筛选/工具进树
  就变成层级，点一下等于换掉中间那一列。
- **三个工具各占一行字**：一个动作一行，扩展段会长出 3 行，条目列表被挤走一半。
